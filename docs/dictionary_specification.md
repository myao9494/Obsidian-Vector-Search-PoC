# 専門用語・類似語辞書機能（Glossary / Synonyms）仕様書

## 1. 概要
本機能は、ユーザーが作成したExcelファイル（`.xlsx`）またはCSVファイル（`.csv`）をシステムが自動的に取り込み、**純粋なベクトル検索（Embedding + FAISS）において、社内特有の専門用語・略称・表記揺れを吸収し、検索精度を劇的に向上させる機能**である。

既存の大量のノートを一切編集することなく、辞書ファイル（例: `glossary.xlsx`）をVault内に配置するだけで、過去のノート資産の救済と、自然文による直感的な質問検索の両立を実現する。

---

## 2. 辞書ファイルのフォーマット仕様

### 2.1 対応ファイル形式
- Excelワークブック: `.xlsx`（推奨・Web UIから直接生成/保存可能）
- CSV / TSV テキスト: `.csv`, `.tsv`, `.txt`

### 2.2 配置場所
- Vaultのルートディレクトリ直下に以下のファイル名で配置すると自動認識されます：
  - `glossary.xlsx`（標準デフォルト）
  - `dictionary.xlsx`
  - `synonyms.xlsx`
  - `glossary.csv`
  - `用語集.xlsx` / `用語集.csv`

### 2.3 列構造の定義

#### 🌟 新推奨フォーマット（2列形式: 類似語列を統合したシンプル設計）
第1列「専門用語」の中に、代表語・同義語・表記揺れをカンマ（`,` や `、`）区切りでまとめて記述します。第1番目の語が代表語（term）、2番目以降が類似語（synonyms）として扱われます。

| 列番号 | 推奨列名（いずれか） | 必須/任意 | 内容・記入例 |
| :--- | :--- | :--- | :--- |
| **第1列** | `専門用語`, `用語`, `Term` | **必須** | 代表語およびカンマ区切りの同義語・略称（例: `PJ-X, プロジェクトX, PJX, PX`） |
| **第2列** | `意味・解説`, `説明`, `解説`, `Description` | 任意 | 用語の意味や文脈の説明（例: `2024年発足の社内基幹システム刷新プロジェクト`） |

#### 🔄 従来の3列フォーマット（完全後方互換）
既存の3列ファイルもそのまま自動認識されます。

| 列番号 | 列名 | 必須/任意 | 内容 |
| :--- | :--- | :--- | :--- |
| **第1列** | `専門用語` | **必須** | 代表語（例: `PJ-X`） |
| **第2列** | `類似語` | 任意 | カンマ区切りの同義語（例: `プロジェクトX, PJX, PX`） |
| **第3列** | `意味・解説` | 任意 | 用語の解説（例: `社内基幹刷新PJ`） |

> **運用のコツ**:
> - **一般的な同義語（MTG, 会議, ミーティング）**: 1列目に `MTG, 会議, ミーティング` とカンマで並べるだけで完了。「意味・解説」は空欄で十分です。
> - **社内造語・コード名（ポチッと君、Zeus）**: 「意味・解説」に一言説明（「交通費・経費精算システム」等）を入れることで、モデルにセマンティクス（文脈）が付与され、劇的にヒット率が向上します。

## 3. Mac対応 Web UI 辞書エディタ (Glossary Editor)

Mac環境等でExcelアプリがインストールされていない場合や、ブラウザから素早く辞書を更新したい場合のために、アプリ内に専用のGUIエディタを搭載しています。

1. **ワンクリック起動**:
   - Vaultインデックスパネルの「📖 専門用語辞書」ボタン、または検索結果上部の「辞書を編集」ボタンからモーダルが起動。
2. **直感的なテーブル編集**:
   - 専門用語（カンマ区切り）と意味・解説をインラインで直接編集・追加・削除。
   - 検索フィルタで大量の登録用語も瞬時に絞り込み。
   - 初期導入用の「💡 サンプル挿入」機能。
3. **Excel (.xlsx) 直接生成 & 保存**:
   - 「Excel (.xlsx) として保存」ボタンを押すだけで、Vault直下に美しいスタイリング付きの `glossary.xlsx` が自動保存されます。
   - バックエンドが即座にファイルを再読み込みし、以降の検索やインデックスに即時反映されます。

## 4. ⚡ SHA-256 ハッシュ & mtime 差分検知キャッシュ（I/O負荷ゼロ化）

Excelファイル（`.xlsx`）は内部がZipアーカイブ形式であるため、毎回の検索リクエストごとにファイルを開いてXMLを展開・パースすると I/O や CPU の無駄な負荷が生じます。

本システムでは、以下の**階層的差分検知キャッシュ（Hierarchical Cache）**を実装しています：

```
[検索リクエスト / 辞書アクセス]
       │
       ▼
【ステップ1: mtime (更新日時) & size (ファイルサイズ) チェック】
・OSの `stat` のみ参照 (所要時間: 0.001ms)
・前回と一致している場合 ➔ [⚡ キャッシュ即時返却 (0.00ms / I/O発生ゼロ)]
       │
       ▼ (mtime または size が変化した場合)
【ステップ2: SHA-256 ハッシュ計算】
・ファイルの `sha256` を高速計算 (所要時間: < 0.1ms)
・前回ハッシュと一致している場合 ➔ メタデータのみ更新してキャッシュ返却
       │
       ▼ (ハッシュ不一致 = 人間が外部で内容を更新・保存した時)
【ステップ3: openpyxl 再パース & インメモリ辞書更新】
・自動で最新エントリを展開し、インメモリキャッシュを即時更新
```

これにより、**「人間が外部でファイルを保存した瞬間に自動検知・再ロードされる利便性」**と、**「通常の検索時にはExcel I/Oが一切発生せず 0.00ms でインメモリ応答する超高速性」**を両立しています。

## 5. システム連携メカニズム

```
[ユーザーの自然文入力]
例:「PJXのプロジェクトでの議事録ってどんなものがあったっけ」
       │
       ▼
【1. 用語検知 & 表記揺れ正規化】
・「PJX」を検知 ➔ 代表語: PJ-X / 同義語: プロジェクトX / 解説: 社内基幹刷新PJ
       │
       ▼
【2. クエリEmbedding補強 (Query Enrichment)】
・モデルに渡すテキスト:
  `検索クエリ: [関連用語: PJ-X => プロジェクトX, 社内基幹刷新PJ] PJXのプロジェクトでの議事録ってどんなものがあったっけ`
       │
       ▼
【3. FAISS ベクトル検索】
・過去ノート「2024-05-10_プロジェクトX_キックオフ.md」と高次元でマッチング
       │
       ▼
【4. UI表示】
・検索結果一覧に「💡 検出された専門用語・同義語」カードを表示
```

### 4.1 表記揺れ正規化（Normalization）
以下の揺らぎを自動的に同一キーとして正規化してマッチングします：
- 全角英数 ⇔ 半角英数（`ｐｊｘ` ⇔ `pjx`）
- 大文字 ⇔ 小文字（`PJ-X` ⇔ `pj-x`）
- ハイフン・アンダースコア・空白の有無（`PJ-X` ⇔ `PJX` ⇔ `PJ_X` ⇔ `PJ X`）

### 4.2 チャンキング時のメタデータ自動注入（Chunk Enrichment）
インデックス作成時、ノート本文中に専門用語・類似語が含まれている場合、チャンク先頭のメタデータに自動で以下を注入してEmbedding化します：
```markdown
[ヘッダー階層] [Tags: #...] [Aliases: プロジェクトX PJX PX] [Context: PJ-X: 2024年発足の社内基幹システム刷新プロジェクト]
本文テキスト...
```
これにより、過去に書かれたノートを書き換えることなく、後から追加された同義語や解説でもベクトル検索で確実にヒットするようになります。

## 5. API 仕様

### 5.1 辞書状態 & エントリ取得 API
- **Endpoint**: `GET /api/dictionary/status`
- **Query Parameter**: `vault_path: str`
- **Response**:
```json
{
  "loaded": true,
  "file_name": "glossary.xlsx",
  "file_path": "/path/to/vault/glossary.xlsx",
  "total_entries": 2,
  "terms": [
    {
      "term": "PJ-X",
      "synonyms": ["プロジェクトX", "PJX", "PX"],
      "description": "2024年発足の社内基幹システム刷新プロジェクト"
    }
  ],
  "entries": [
    {
      "term": "PJ-X",
      "synonyms": ["プロジェクトX", "PJX", "PX"],
      "description": "2024年発足の社内基幹システム刷新プロジェクト",
      "terms": "PJ-X, プロジェクトX, PJX, PX"
    }
  ]
}
```

### 5.2 辞書保存 API (Web UI用)
- **Endpoint**: `POST /api/dictionary/save`
- **Request Body**:
```json
{
  "vault_path": "/path/to/vault",
  "file_name": "glossary.xlsx",
  "entries": [
    {
      "terms": "PJ-X, プロジェクトX, PJX, PX",
      "description": "2024年発足の社内基幹システム刷新プロジェクト"
    },
    {
      "terms": "ポチッと君, ポチット, pochito",
      "description": "交通費・経費精算システム"
    }
  ]
}
```
- **Response**:
```json
{
  "success": true,
  "message": "専門用語辞書を保存しました: glossary.xlsx",
  "file_name": "glossary.xlsx",
  "file_path": "/path/to/vault/glossary.xlsx",
  "total_entries": 2,
  "entries": [ ... ]
}
```

### 5.3 検索 API の拡張
- **Endpoint**: `POST /api/search`
- **Response**: 既存の検索結果フィールドに加え、`detected_terms` 配列が返却されます。
```json
{
  "query": "PJXのプロジェクトでの議事録ってどんなものがあったっけ",
  "results": [ ... ],
  "detected_terms": [
    {
      "term": "PJ-X",
      "synonyms": ["プロジェクトX", "PJX", "PX"],
      "description": "2024年発足の社内基幹システム刷新プロジェクト"
    }
  ]
}
```
